:::tldr
Агент начинается с обычного чата. В этой части получаем API-ключ, ставим SDK и пишем `chat.ts`: терминальный чат, который стримит ответ, помнит историю и показывает, сколько токенов ушло.
:::

Это первая часть серии, где мы шаг за шагом соберём своего AI-агента: от первого запроса к модели до сервиса с инструментами, MCP и OAuth. Без фреймворков, на TypeScript и [Bun](https://bun.sh), каждый шаг можно запустить.

## План серии

1. **Первый разговор с моделью.** Ключ, SDK, стриминг, история. *Эта часть.*
2. **[Агентный цикл](/blog/ru/agent-2-agent-loop/).** Инструменты, harness, подтверждение опасных действий.
3. **MCP.** Подключаем готовые MCP-серверы к агенту и пишем свой.
4. **OAuth.** Удалённые MCP-серверы, которые требуют входа пользователя.
5. **Контекст и деньги.** Кэширование промпта, сжатие истории, лимиты.
6. **В прод.** Агент как HTTP-сервис, логи, проверки качества, безопасность.

## Что такое агент

Если убрать маркетинг, агент состоит из трёх частей:

- **модель**, которая по тексту решает, что делать дальше;
- **инструменты**, функции в вашем коде, которые модель может попросить вызвать: прочитать файл, выполнить команду, сходить в API;
- **цикл (harness)**, который передаёт модели историю, выполняет запрошенные инструменты, возвращает результаты и повторяет, пока задача не решена.

Модель здесь самая дорогая и самая заменяемая часть. Всё интересное происходит в цикле, и его мы будем писать сами. Но сначала нужно научиться просто разговаривать с моделью.

## Шаг 1. Ключ

Я буду использовать Claude от Anthropic, но устройство у всех коммерческих API похожее, и переписать код под другого провайдера несложно.

1. Зарегистрируйтесь в [консоли Anthropic](https://platform.claude.com) и пополните баланс: оплата за токены, на эксперименты из этой серии уйдёт несколько долларов.
2. В разделе API Keys создайте ключ.
3. Положите его в переменную окружения:

```bash
export ANTHROPIC_API_KEY="sk-ant-..."
```

:::warning
Не коммитьте ключ в репозиторий и не вставляйте его в код. SDK сам прочитает `ANTHROPIC_API_KEY` из окружения.
:::

## Шаг 3. Первый запрос

```ts
// hello.ts
import Anthropic from "@anthropic-ai/sdk";

const client = new Anthropic();

const reply = await client.messages.create({
  model: "claude-opus-5-5",
  max_tokens: 16000,
  messages: [{ role: "user", content: "Объясни, что такое агент, в одном предложении." }],
});

for (const block of reply.content) {
  if (block.type === "text") console.log(block.text);
}
console.log(reply.stop_reason, reply.usage);
```

```bash
bun hello.ts
```

Обратите внимание на три вещи в ответе.

- **`content` это массив блоков**, а не строка. Кроме `text` там бывают блоки размышлений (`thinking`) и вызовы инструментов (`tool_use`). Во второй части именно на них построен агент.
- **`stop_reason`** объясняет, почему модель остановилась: `end_turn` (договорила), `max_tokens` (упёрлась в лимит), `tool_use` (хочет вызвать инструмент), `refusal` (отказалась отвечать).
- **`usage`** показывает, сколько токенов ушло на вход и выход. По нему считаются деньги: у Opus 5.5 это 4 доллара за миллион входных токенов и 20 за миллион выходных.

## Шаг 4. История

API не хранит разговор. Каждый запрос отправляет всю историю целиком, а «память» модели это просто массив `messages`, который вы растите сами:

```ts
const messages: Anthropic.MessageParam[] = [
  { role: "user", content: "Меня зовут Миша." },
  { role: "assistant", content: "Привет, Миша!" },
  { role: "user", content: "Как меня зовут?" },
];
```

Из этого следуют две вещи, которые понадобятся позже. Каждый следующий запрос дороже предыдущего, потому что история растёт. И вы полностью контролируете, что модель «помнит»: можно вырезать, сжать или подменить что угодно. Этим займёмся в пятой части.

## Шаг 5. Чат со стримингом

Ответ модели может генерироваться десятки секунд. Чтобы не смотреть в пустой экран, используем стриминг: текст печатается по мере генерации, а в конце `finalMessage()` отдаёт полный ответ.

```ts
// chat.ts
import Anthropic from "@anthropic-ai/sdk";
import { createInterface } from "node:readline/promises";

const client = new Anthropic(); // ключ берётся из ANTHROPIC_API_KEY
const rl = createInterface({ input: process.stdin, output: process.stdout });

const system = "Ты лаконичный помощник программиста. Отвечай по делу.";
const messages: Anthropic.MessageParam[] = [];

while (true) {
  const input = (await rl.question("\n> ")).trim();
  if (!input || input === "/exit") break;

  messages.push({ role: "user", content: input });

  const stream = client.messages.stream({
    model: "claude-opus-5-5",
    max_tokens: 16000,
    output_config: { effort: "low" },
    system,
    messages,
  });

  stream.on("text", (delta) => process.stdout.write(delta));
  const reply = await stream.finalMessage();

  if (reply.stop_reason === "refusal") {
    console.log("\n[модель отказалась отвечать]");
    messages.pop(); // не тащим этот вопрос дальше в историю
    continue;
  }

  // В историю кладём весь content целиком, а не только текст
  messages.push({ role: "assistant", content: reply.content });

  const { input_tokens, output_tokens } = reply.usage;
  console.log(`\n[${input_tokens} in / ${output_tokens} out]`);
}

rl.close();
```

```bash
bun chat.ts
```

Поговорите с ним пару минут и посмотрите на счётчик токенов: входных становится больше с каждым сообщением, потому что история уходит в каждый запрос заново.

## Разбор

**`system`** задаёт роль и правила. Это не сообщение пользователя: модель относится к нему как к инструкции от разработчика. В агенте здесь будет описание рабочей папки и правил поведения.

**`effort`** управляет тем, насколько глубоко модель думает перед ответом. Для чата хватает `low`, для агента, который правит код, поставим `medium` или `high`. Чем выше, тем медленнее и дороже, но точнее на сложных задачах.

**`reply.content` целиком в историю.** Соблазнительно сохранить только текст ответа, но в `content` лежат и служебные блоки, например размышления модели. API ожидает получить их обратно в том же виде. В агенте это станет критично: там в `content` будут вызовы инструментов, и без них следующий запрос просто не пройдёт.

**`max_tokens`** это потолок длины ответа, а не цель. Модель не пытается его заполнить. Если поставить слишком мало, ответ оборвётся на полуслове с `stop_reason: "max_tokens"`.

:::note
Хотите сэкономить на экспериментах? Замените модель на `claude-haiku-5-5`: она в десятки раз дешевле и для чата вполне годится. Для агента, который самостоятельно решает многошаговые задачи, лучше оставить Opus.
:::
